# スプラトゥーン3 ブキルーレットBot

Node.js 24 / TypeScript / discord.js。WindowsとUbuntuで動作する構成です。

- `/ping`: 接続確認。
- `/roulette`: 実行者のVCメンバーを取得し、条件設定パネルを表示します。

`/roulette` の `category` 欄で初期ブキ種を指定する既存の機能も利用できます。
例: `/roulette category:チャージャー`。省略または「すべて」なら初期条件は指定なしです。

## 条件設定パネル

1. VCに参加し、テキストチャンネルで `/roulette` を実行します。
2. ブキ種・射程・サブ・スペシャルを複数選択し、特殊ルールを選びます。
3. 「抽選する」で各メンバーに1つずつブキを割り当てます。
4. 「同じ条件で再抽選」または「条件を変更」で続けて操作できます。

各メニュー内はOR、異なるメニュー間はANDです。選択をすべて外すとその条件を指定しません。
「条件リセット」はすべての条件を初期状態に戻します。
候補が0件、または特殊ルールに必要な種類数が足りない場合は理由を表示し、抽選ボタンを無効化します。

特殊ルールは「なし」「全員違うブキ」「全員違うブキ種」「全員同じブキ種」です。
「全員違うブキ」はデコ・コラボなどのセット違いも別ブキとして扱います。
「全員同じブキ種」では同じブキが複数人に出る場合があります。
同じ・違うブキ種の抽選ではブキ種を等確率で選び、その種の候補からブキを等確率で選びます。

射程はstat.inkの `matching_range` を基にしたBot独自の分類です。
15未満＝短射程、15以上22未満＝中射程、22以上＝長射程とします。
これは公式の短・中・長区分ではなく、閾値は `src/roulette/logic.ts` で調整できます。

対象は実行時のVCにいる人間のメンバー1〜25人です（Botを除く）。
再抽選・条件変更時も同じメンバーを使用します。VCの出入りを反映するには `/roulette` を実行し直します。
VCにBotを接続する必要はありません。`GuildVoiceStates` Intentを利用します（特権Intentではありません）。

パネルは公開されますが、操作できるのは実行者のみです。
状態はDBやファイルへ保存せず、パネルごとにメモリ上で保持します。
操作から30分で期限切れになり、期限切れ・Bot再起動後の操作には再実行を案内します。
期限切れメッセージ自体は残りますが、そのパネルの操作はできません。
Components V2を利用して5つのメニューとボタンを同じパネルに表示しています。

各ブキセットを同じ確率で抽選します。コラボ・デコなどの別セットを含み、
性能が同じ外見違いのレプリカは除外します。

## 初期設定（Windows / PowerShell）

```powershell
npm ci
Copy-Item .env.example .env
```

既存の `.env` がある場合はコピーで上書きせず、不足している項目を追記してください。

- `DISCORD_TOKEN`: BotのToken。チャットなどに共有したTokenは再発行してください。
- `DISCORD_CLIENT_ID`: Developer Portalの「General Information」にあるApplication ID。
- `DISCORD_GUILD_ID`: 開発用サーバーのID。Discordの「詳細設定」で開発者モードを有効にし、サーバーを右クリックしてIDをコピーします。

TokenをソースコードやGitに保存しないでください。

## コマンド登録と起動

```powershell
npm run deploy:commands
npm run dev
```

登録成功後、指定したサーバーで `/ping` を実行すると `Pong!` が返ります。
登録はコマンド定義を変更したときに実行します。起動のたびに登録する必要はありません。
開発実行はファイル変更時に再起動します。終了は `Ctrl+C` です。

ビルド済みコードを実行する場合:

```powershell
npm run build
npm start
```

通常のテキストチャンネルで使います。Botの権限は「チャンネルを表示」「メッセージを送る」「リンクを埋め込み」。
スラッシュコマンドを使えるよう、インストールには `bot` と `applications.commands` のスコープを使用します。
利用者にもチャンネルでアプリコマンドを使う権限が必要です。
この構成では特権Intentの有効化は不要です。

## ブキデータと検証

ブキデータは [stat.ink API](https://stat.ink/api/v3/weapon) の日本語データから生成し、
`src/data/weapons.ts` をGit管理します。通常の起動・抽選時は外部APIへアクセスしません。
データの取得日はファイル先頭に記録しています。

```powershell
npm run data:update
npm test
```

データ更新は手動で行い、変更内容を確認してGitへ保存してください。
本番では開発環境と別の `.env` を用意し、GitHubからclone/pull後に
`npm ci`、`npm run build`、`npm start` を実行します。
VPSでの常時稼働にはsystemdを使います。配置・更新・ログ確認の手順は
[deploy/README.md](deploy/README.md) を参照してください。
